Camera diagnostics

Whether this browser can talk to a camera over USB depends on the address this page was loaded from, not on which machine the camera is plugged into. Browsers only expose USB to a secure context: an HTTPS origin, or localhost. Plain HTTP to a LAN address never qualifies, even when the camera is on the same desk.

Camera

Picking a device needs a click, so this cannot run automatically. Connect the camera by USB, set it to PC Connection or RAW CONV. mode, then run the probe and choose it from the browser's picker.

  • Device selected not run waiting
  • Opened not run waiting
  • Bulk endpoints not run waiting
  • Interface claimed not run waiting
  • PTP session not run waiting

If claiming fails, something else already holds the camera. On Linux that is usually gvfs-gphoto2-volume-monitor, which mounts PTP cameras the moment they are plugged in. On macOS it is Photos, and on Windows the device is claimed as MTP. The browser cannot evict any of them, so the fix is on the host and is the same one the server-side path needs: see docs/camera_usb_access.md.

Selecting a device also needs permission on the raw USB node. On Linux that normally arrives with libgphoto2, whose udev rules give every still-image class device to the plugdev group. Installing libgphoto2 for its rules while disabling its automount is the combination that works.

Filtering by vendor {{ diagnostics.vendor_id_label }} hides non-Fujifilm devices from the picker. If the camera does not appear, run the unfiltered probe to see whether the browser can see it at all.
